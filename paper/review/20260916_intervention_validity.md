## Decision

## Defects addressed

1. **Incomplete G object.** A phase-only state omits `_last_observation_token`. The mathematical memory now includes phase and consumed event token. The model still receives history, so this is not a sufficient belief state or classical finite-memory optimal controller.
2. **Base/dynamic mismatch.** Base previously accepted public fault/condition/revision events and could enter Monitor/Revise. Public events and direct dynamic-state predecessors now fail in base before cache mutation. Valid event-free base requests remain unchanged in the tested fixtures. Historical event-containing base runs are not claimed equivalent.
3. **Confounded dynamic memory comparison.** Previously only dynamic no-memory removed historical state metadata. All prospective dynamic profiles now use the same sanitation. This changes full-dynamic inputs: use a new dynamic-history-matched cohort, not archived full-dynamic controls.
4. **Inactive base ablations.** Under the explicit no-event assumptions, previous state and replanning cannot reach their effective branches. The proof establishes a null manipulation; the tests inspect six representative progress histories rather than claiming exhaustive runtime reachability.

## Remaining attribution boundaries

The cue includes a label and stage instruction. The mask may itself disclose stage information. Four-cell effects therefore concern the implemented cue package and tool interface, not pure topology, all state information or a causal mediation estimate of mask loss. The common knowledge source stays fixed; stronger claims beyond additional procedural wording need the planned information-matched control.

A repeated-event fixture changes full/no-memory/no-replanning states, but Monitor and Revise expose the same tools. A changed label or prompt does not prove that the model revises its next action. Shared-Runner reachability, model responses and PHM task effects remain necessary.

The eleven-successful-operator replay threshold can be reached by repetitions. Its existing definition is retained and described as progress, not distinct-feature sufficiency. Changing it now would introduce another treatment. The cardinality control committed concurrently is preserved; the older local patch is not applied.
