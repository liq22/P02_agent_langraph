# Verified Literature Matrix

Primary sources were checked through 2026-09-18. The relation column contrasts positively documented study objects with the registered Generic-base graph method; an abstract is not used to infer that an unmentioned mechanism is absent.

| citekey | primary source | exact claim used | relation to the registered graph contrast |
|---|---|---|---|
| `kong2026timesagemt` | arXiv `2606.01498v1`, full text | TimeSage-MT provides 240 multi-turn tasks and evaluates structured, skill-guided and code-enabled time-series agents across eight domains. | The registered P2 comparison instead varies an explicit decision-state controller over one fixed Generic vibration-agent world. |
| `wu2026timeart` | arXiv `2601.13653v1`, full text | TimeART trains a tool-using model on expert time-series tool trajectories for time-series question answering. | P2 records a fixed model's observed PHM action/state trajectory and estimates Graph minus Generic rather than training on tool trajectories. |
| `das2026phmforge` | arXiv `2604.01532` v3 | PHM tool orchestration can be evaluated with MCP-native algorithm tools and execution traces, including verification, distractor and data-discovery controls. | Its industrial-lifecycle scope is broader than this matched graph-policy study; no quantitative result is reused. |
| `rayfield2025reactiot` | Official ACL Anthology paper, DOI `10.18653/v1/2025.emnlp-industry.24`, Sections 2--4 | ReActXen combines a ReAct executor with Review, Reflect, and Distillation components plus a Tiny Trajectory Store for structured SCADA queries; IoTBench contains more than 400 tasks across five industrial sites. | P2 uses one Generic-derived treatment with a deterministic controller and no treatment-only reviewer, reflector, distiller, or trajectory store. |
| `wu2024stateflow` | arXiv `2403.11322v5`, Sections 2--4, and the official COLM 2024 accepted-paper record | StateFlow models LLM task solving as a state machine, separates process grounding through states and transitions from actions within a state, and allows transitions to use rules or an LLM over context history. Its state output functions can invoke prompts, models, and tools. | StateFlow is the direct workflow precedent, so P2 does not claim state-machine organization as novel. |
| `zhou2026codereact` | Official AAAI proceedings paper, DOI `10.1609/aaai.v40i47.41453`, full text | CodeReAct embeds executable Python in a Thought--Action--Observation loop over structured Business Objects and evaluates outer-loop reflection and adaptive temperature over 36 maintenance utterances. | P2 constrains tool visibility from explicit public-trajectory state; it does not add executable Python or adaptive model control. |
| `zhang2026spiral` | Official AAAI proceedings paper, DOI `10.1609/aaai.v40i43.40975`, full text | SPIRAL represents tool-use planning as state-space search and embeds Planner, Simulator, and Critic roles in an MCTS loop; the Simulator predicts plausible next observations and the Critic supplies dense reflective feedback. | P2 is not search over simulated outcomes: its states are derived from recorded Benchmark observations/actions, and its matched treatment adds no planner, simulator, critic, or MCTS. |
| `lessmeier2016conditionMonitoring` | Paderborn Bearing DataCenter and PHM Society DOI `10.36001/phme.2016.v3i1.1577` | Dataset origin, vibration and motor-current acquisition, and canonical citation. | This source defines the dataset, not the graph-policy treatment. |
| `yao2023react` | arXiv `2210.03629` v3 / ICLR 2023 paper | ReAct interleaves reasoning traces and environment actions so the model can update plans and handle exceptions. | P2 retains the same Generic reasoning/action base and makes the treatment's current state and legal tool subset explicit in the shared rollout. |
| `shinn2023reflexion` | arXiv `2303.11366` | Reflexion uses linguistic feedback and an episodic memory buffer to improve decisions in subsequent trials without updating model weights. | P2 instead studies deterministic within-rollout state control over matched Generic episodes. |
| `liu2023agentbench` | arXiv `2308.03688` | AgentBench identifies long-term reasoning, decision-making, and instruction following as common obstacles across eight interactive environments. | P2 evaluates an explicit PHM state/transition treatment together with task, rollout, recovery, and cost endpoints. |
| `hansen1997` | NeurIPS 1997 proceedings paper | Finite-state controllers and policy iteration for partially observable MDPs predate LLM workflow agents. | It constrains novelty: P2 does not introduce the general idea of a finite controller or state-associated actions. |
| `huang2022masking` | FLAIRS 2022 / arXiv `2006.14171` | Invalid-action masking changes the sampled action support and has an established policy-gradient analysis. | P2's schema gate is broader: it changes model input, implicit phase information, and executable action sequences, so it is not treated as pure masking. |
| `evendar2006` | JMLR 7:1079--1105 | Action elimination requires confidence information about values and supplies stopping conditions under stated assumptions. | P2 does not infer that an omitted PHM tool is low-value from the gate or trajectory alone. |
| `jiang2016` | ICML 2016, PMLR 48:652--661 | Off-policy value evaluation estimates a target policy from data generated by another policy and requires explicit estimator assumptions. | Executed Graph logs do not by themselves identify the value of actions excluded by the gate. |
| `khan2024` | ICML 2024, PMLR 235:23734--23757 | Without overlap, off-policy values are only partially identified unless additional structure is imposed. | This supports reporting bounds/unknowns rather than assigning an invented value to unobserved PHM continuations. |
| `yao2024tau` | arXiv `2406.12045` | tau-bench introduces `pass^k` to measure tool-agent reliability over repeated trials. | P2's first-attempt endpoint is an operational outcome definition, not a claim to invent repeated-run reliability evaluation. |
